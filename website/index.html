Features

Everything a live service needs

One application, one renderer, built to run start to finish without a hiccup.

One unified renderer

Preview, projector output, OBS, and thumbnails all render through the exact same engine — what you see is exactly what goes live.

OBS Browser Source support

Paste one URL into OBS and stream or record your service — no capture card, no second renderer.

Local & cloud sync

Run entirely on your church's own network, or sync over the internet when volunteers are remote.

Offline-first architecture

Nothing about running a service depends on the internet or a server you don't control.

Presentation library

Every service is saved, searchable, and ready to reopen next week — nothing is ever really gone.

Component-based slides

Scripture, lyrics, and lower-thirds are built from the same elements, styled independently.

Autosave

Every edit is saved as you make it. No save button, no losing your place mid-service.

Controller & output separation

Run the control surface on a laptop and the output on the projector PC — independent, purpose-built screens.

Why OmniDeck

Built to run a service — not just display lyrics.

Most presentation tools are built around a slideshow: one file, one deck, one timeline. A church service isn't that. It's scripture pulled live, songs with verses that repeat out of order, a video that starts on cue, an offering announcement dropped in without warning, and a lower-third that needs to stay up while everything else keeps moving.

OmniDeck is built around that reality. Everything — scripture, lyrics, media, announcements — lives in one playlist, on one renderer, so what your team previews is exactly what the congregation sees. It runs fully offline, saves as you go, and keeps the controller and the output on independent screens, so a laptop hiccup never touches what's on the projector.

  • Scripture, lyrics, media, and announcements in one playlist
  • Runs fully offline — nothing depends on a server you don't control
  • Every edit autosaves — mid-service, mid-sentence
  • Controller and output run as independent, purpose-built screens
